# Tetris CPC v0.5 Release Notes

Version 0.5 is the first DSK-only overlay build. It keeps v0.4 available as
the monolithic/CDT-friendly build, while v0.5 focuses on freeing RAM for future
game features.

## User Entry Point

Insert `dist\TETRIS.DSK` or `dist\TETRIS-v0.5.DSK` and run:

```basic
RUN"TETRIS.BIN"
```

The visible catalog intentionally contains only the small boot file. The
resident game payload and runtime overlays are stored in fixed hidden sectors.

## Official Build

Use:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build_overlay_dsk.ps1
```

Main outputs:

- `dist\TETRIS.DSK`: current v0.5 release disk.
- `dist\TETRIS-v0.5.DSK`: versioned v0.5 release disk.
- `dist\TETRIS.BIN`: AMSDOS-headered direct-FDC boot file for reference.
- `dist\TETRIS-v0.5.BIN`: versioned copy of the boot file.

There is no v0.5 CDT artifact because the v0.5 loader relies on disk sectors.

## Current Memory Layout

- Resident game payload: `0x1000-0x2E1C`, 7709 bytes.
- Resident growth before overlay workspace: about 8.5 KB raw, about 7 KB guarded.
- Splash/title overlay: load `0x5000`, 16175 bytes, tracks 30-33.
- Runtime font/text/tables overlay: load `0x5000`, 864 bytes, track 35.
- Menu code overlay: load `0x5400`, 966 bytes, padded to 3 sectors, track 36.
- Gameplay music overlay: load `0x9400`, 686 bytes, track 34.
- CPC screen RAM remains `0xC000-0xFFFF`.

Practical future feature budget is about 12 KB immediately in the current
overlay layout, about 20-25 KB with planned overlay reuse, and roughly 35 KB if
we deliberately use all safe split regions.

## Verified Behavior

- Direct-FDC boot reads the resident payload from hidden sectors.
- Splash and title music load from overlay sectors.
- Runtime font/text/key tables reload after splash.
- Gameplay music stays persistent at `0x9400`.
- Menu/redefine-key code loads as a 3-sector runtime overlay.
- Game can return from game over to the menu; the 3-sector menu overlay reduces
  the previous return delay.
