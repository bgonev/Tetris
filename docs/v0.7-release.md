# Tetris CPC v0.7 Release Notes

Version 0.7 extends the DSK-only direct-FDC overlay model with persistent
high scores, gameplay-screen refinements, and randomized 7-piece gameplay
bags. The patched v0.7 release also includes the CPC 464 + ULIfAC USB raw-FDC
write fix for high-score saves.

## User Entry Point

Insert `dist\TETRIS.DSK` or `dist\TETRIS-v0.7.DSK` and run:

```basic
RUN"TETRIS.BIN"
```

The visible catalog intentionally contains only the small boot file. The
resident game payload, runtime overlays, and high-score sector are stored in
fixed hidden sectors.

## Official Build

Use:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build_overlay_dsk.ps1
```

Main outputs:

- `dist\TETRIS.DSK`: current v0.7 release disk.
- `dist\TETRIS-v0.7.DSK`: versioned v0.7 release disk.
- `dist\TETRIS.BIN`: AMSDOS-headered direct-FDC boot file for reference.
- `dist\TETRIS-v0.7.BIN`: versioned copy of the boot file.

There is no v0.7 CDT artifact because the loader relies on disk sectors. Keep
v0.4 as the monolithic/CDT-friendly build.

## Current Memory Layout

- Boot loader: load/run `0x0800`, 851 bytes.
- Resident game payload: load `0x1000`, run `0x31DA`, highest `0x3E96`.
- Resident payload bytes: 11927, 24 sectors, tracks 20-22.
- Gameplay screen overlay: load `0xC000`, 16384 bytes, tracks 23-26.
- High-score sector: buffer `0x4E00`, 512 bytes, track 27.
- Splash/title overlay: load `0x5000`, 16175 bytes, tracks 30-33.
- Gameplay music overlay: load `0x9400`, 686 bytes, track 34.
- Runtime font/text/tables overlay: load `0x5000`, 886 bytes, track 35.
- Menu/redefine-key code: resident in the main payload.
- CPC screen RAM remains `0xC000-0xFFFF`.

## Gameplay Screen

- Generated by `tools\generate_gameplay_background.ps1`.
- Source mock: `assets\new_gameplay_layout.jpg`.
- Preview output: `assets\gameplay_mode0_preview.png`.
- Runtime overlay binary: `obj\overlay\gameplay_screen.bin`, loaded to screen

- Dome blue pixels were remapped to green for the v0.7 tower treatment.
- HUD is compact and left-aligned at the top-left:
  `SCORE 00000`, `LEVEL 001`, `LINES 0000`.

## Piece Randomization

- Gameplay pieces use a shuffled 7-piece bag.
- The bag is reset for each new game and refilled only after all seven pieces
  have been dealt.
- The RNG is stirred from player timing during splash, menu, key-selection,
  game-over, and name-entry waits.
- Menu title colours use separate random colour draws and no longer consume
  gameplay pieces.

## High Scores

- Game-over screen shows animated `GAME OVER` text plus a five-entry high-score
  table.
- `PRESS ANY KEY` text was removed from game over.
- Default table:
  - `MARIJA 05000`
  - `MEGLENA 00870`
  - `MAKSIM 00640`
  - `BOJANA 00420`
  - `BORO 00250`
- Player scores qualify when nonzero and at least equal to the fifth score.
- Name entry accepts A-Z, up to 7 characters, with Enter/Return submit and Del
  backspace.
- Animation continues during name entry and while waiting for dismissal.
- Scores are stored as five ASCII digits in the hidden sector.
- High-score saves use the direct-FDC write path and are non-fatal on save
  failure.
- On ULIfAC, the write loop ignores `DIO` while `EXM=1` and feeds data when
  `RQM=1`. Diagnostics showed ULIfAC can report `MSR F0` during write
  execution; reading the data register in that state freezes, while writing the
  next byte works.

## Verified Behavior

- Direct-FDC boot reads the resident payload from hidden sectors.
- Splash/title overlay and title music load correctly.
- Runtime font/text/key tables reload after splash.
- High-score sector loads after runtime text/tables.
- Gameplay screen overlay loads before the board and HUD are drawn.
- Gameplay music stays persistent at `0x9400`.
- First and next pieces are generated from the randomized 7-piece bag.
- Menu/redefine-key flow runs resident, so returning from game over does not
  perform a menu-code overlay reload.
- Official release artifacts were built by `tools\build_overlay_dsk.ps1`.
- Patched high-score save was verified on real CPC 464 + ULIfAC USB after the
  `FIX6` ignore-`DIO` write-loop test.
